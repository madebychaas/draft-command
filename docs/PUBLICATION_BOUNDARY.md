# Publication Boundary

Use this checklist before anything from the private Draft Command repository is published.

## Safe to publish

- product name and category
- high-level architecture
- screenshots using sanitized or intentionally public data
- high-level proof metrics
- UX principles
- fail-closed philosophy
- adversarial-development methodology
- public-safe examples
- selected code that has been explicitly sanitized

## Do not publish by default

- Sleeper league ID
- user ID
- real private league exports
- manager identifiers
- private group-chat content
- normalized signals derived from private messages unless fully anonymized and justified
- operational SQLite database
- local file paths containing personal information
- credentials or API tokens
- exact decision weights
- private heuristics
- source-specific edge logic
- unpublished strategic playbooks

## Sleeper / platform similarity

The public interface should not imitate another fantasy platform’s trade dress.

Prefer:

- Draft Command’s own purple/gold identity
- unique information hierarchy
- unique terminology
- unique decision-first interaction model

Avoid:

- cloning another platform’s navigation
- copying its card layout or distinctive iconography
- implying affiliation or endorsement

## Player and team intellectual property

Colors can be used as aesthetic inspiration, but official team marks, league marks, and photography require separate rights considerations.

For player imagery, use licensed provider media or neutral substitutes. Never label generated likenesses as official photographs.
